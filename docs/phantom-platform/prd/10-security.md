## 1. 功能概述

安全与合规是 Phantom IM 作为公开社交产品的信任基座，覆盖四条主线：一是**内容与行为治理**——通过举报、审核、处置形成"发现-判定-处理-反馈"的闭环，抑制违规内容与骚扰行为；二是**账号处置与申诉**——对违规账号实施分级处置，并保障用户的申诉权利，避免误伤；三是**垃圾消息与骚扰防护**——通过频率限制与非好友消息限制，从产品机制上降低骚扰发生概率，而非仅靠事后举报；四是**数据隐私**——保障用户对自身数据的知情权、可携权与被遗忘权，并为未成年人提供额外保护。

本篇聚焦产品层的规则、流程与交互，风控算法、审核模型等技术实现不在本篇展开。

## 2. 用户场景（User Story）

1. 作为普通用户，当我收到陌生人发来的骚扰消息时，我希望能够一键举报并拉黑对方，让对方无法再联系我，这样我才能安心使用产品。
2. 作为群成员，当群内出现广告刷屏或违规内容时，我希望能够举报该消息或该群，并说明理由，让平台介入处理。
3. 作为被误判的用户，当我的账号因误判被禁言或封号时，我希望能够通过申诉通道说明情况并获得复核，而不是投诉无门。
4. 作为注重隐私的用户，当我想了解平台保存了我的哪些数据时，我希望能够导出个人信息；当我决定停止使用产品时，我希望注销后我的数据会被真正删除。
5. 作为未成年用户的监护人，我希望产品对未成年人的陌生人社交与内容接触有额外限制，让孩子使用更安全。

## 4. 关键交互流程

### 4.1 举报处理流程

1. 用户在消息气泡/用户主页/群资料页选择"举报"
2. 用户选择举报理由分类（SEC-04），可选填文字说明与截图
3. 系统受理举报，生成举报单，进入自动初筛（风控规则匹配）
4. 命中高置信度规则的举报，自动完成处置（如自动隐藏消息、自动警告）
5. 未命中自动规则的举报，转入人工审核队列
6. 审核完成后，系统根据结果对被举报对象执行处置（警告/禁言/封号/不处置）
7. 系统向举报人推送处理结果通知（SEC-05），向被处置对象推送处置通知

### 4.2 账号处置与申诉流程

1. 触发条件成立（举报审核结论、风控规则命中、人工巡查发现）
2. 系统根据违规等级与历史记录，匹配处置类型（警告/禁言/封号）
3. 处置生效，账号侧同步展示处置状态与原因、剩余时长（禁言/限时封号）
4. 用户在处置提示页或设置中点击"申诉"，填写申诉理由与证明材料
5. 申诉进入复核队列，人工复核处置是否合理
6. 复核结论为误判：撤销处置并恢复账号状态，通知用户
7. 复核结论为维持：告知用户维持原处置及依据，不再受理同一事件的重复申诉

### 4.3 敏感内容实时拦截流程

1. 用户在单聊/群聊输入框发送文本或图片消息
2. 消息在客户端提交后，先经过服务端风控引擎实时扫描（文本关键词/图像识别）
3. 判定为违规：消息拦截，不投递给接收方，发送者收到拦截提示（SEC-12）
4. 判定为疑似违规：消息正常投递，同时标记异步复审，复审确认违规后触发撤回或后续处置
5. 判定为正常：消息正常投递，无感知

### 4.4 非好友消息与频率限制流程

1. 非好友用户 A 向用户 B 发送消息
2. 消息进入 B 的"消息请求"分区，B 收到轻量提醒（不计入主会话未读角标）
3. B 选择"同意"：会话转为正常会话，后续消息正常显示；B 选择"拒绝"或"拉黑"：A 后续消息不再送达
4. 若 A 在单位时间内对多个非好友发起会话请求超过阈值，触发频率限制，暂时禁止其发起新的陌生人会话

### 4.5 数据导出与账号注销流程

1. 用户在设置中选择"导出我的数据"，系统校验冷却期（24 小时内仅可申请一次）
2. 系统异步生成数据文件（资料、好友关系、群组列表等），生成完成后通过站内通知提醒用户下载
3. 用户在设置中选择"注销账号"，系统提示注销后果并要求二次确认
4. 账号进入 7 天冷静期（与 [账号与用户体系](01-account.md) AC-16 一致），期间账号状态为"待注销"，用户可随时登录撤销注销
5. 冷静期结束且未撤销：系统按隐私政策承诺删除或匿名化账号数据，账号无法再登录

### 4.6 未成年人模式开启流程

1. 用户在设置中选择开启"青少年模式"，或由监护人在实名信息核验后代为开启
2. 系统提示该模式下的限制范围（陌生人消息、陌生群组、内容审核阈值），用户确认后生效
3. 模式生效期间，用户尝试接收非好友消息或加入陌生群组时，系统直接拦截并提示"当前处于青少年模式，该操作不可用"
4. 用户可随时在设置中关闭该模式（未成年人账号关闭时需二次确认或监护人验证，具体验证方式由后续独立方案确定）

## 5. 验收标准

**SEC-01/02/03 举报入口与理由**
- Given 用户在消息气泡长按弹出操作菜单，When 点击"举报"并选择理由后提交，Then 举报单创建成功且用户收到"已提交，我们会尽快处理"的提示
- Given 用户在群资料页点击"举报该群"，When 未选择举报理由直接提交，Then 系统阻止提交并提示"请选择举报理由"

**SEC-04 举报理由分类**
- Given 用户发起举报，When 打开理由选择列表，Then 展示垃圾广告、色情低俗、暴力血腥、诈骗、骚扰辱骂、违法信息、侵犯隐私、其他共 8 类选项

**SEC-05 处理结果通知**
- Given 一条举报已完成人工审核，When 处置结论生成，Then 举报人在 3 个工作日内收到站内结果通知，通知内容不包含被举报人的具体处置细节

**SEC-06/07/08 账号处置分级**
- Given 账号首次出现轻微违规，When 审核判定成立，Then 系统下发警告通知并记录违规次数，账号功能不受限
- Given 账号存在中等程度违规，When 处置生效，Then 账号在禁言时长内无法发送任何消息，但可正常接收与查看历史消息
- Given 账号严重违规或警告/禁言后再次违规，When 处置生效，Then 账号被封号，尝试登录时提示封禁原因与解封时间（如为限时）

**SEC-10/11 内容风控审核**
- Given 用户发送包含违规关键词的文本消息，When 消息提交，Then 消息被实时拦截，不会投递给接收方
- Given 用户发送包含违规内容的图片，When 消息提交，Then 图片被拦截并提示"图片内容违规，发送失败"

**SEC-12 拦截提示**
- Given 消息被内容风控拦截，When 提示展示给发送者，Then 提示语说明"内容包含敏感信息"等通用原因，不回显具体触发的敏感词

**SEC-13 频率限制**
- Given 用户在 1 分钟内发送消息超过系统阈值，When 达到阈值，Then 后续发送被限流并提示"操作过于频繁，请稍后再试"

**SEC-14 非好友消息限制**
- Given 用户 A 与用户 B 非好友关系，When A 向 B 发送首条消息，Then 消息进入 B 的消息请求分区，且不触发主会话列表未读角标增加

**SEC-15 拉黑联动**
- Given 用户 B 已将用户 A 拉黑，When A 尝试发送消息或好友申请给 B，Then 请求在服务端被拒绝，B 不会收到任何通知

**SEC-17 注销数据删除**
- Given 用户提交账号注销申请并经过冷静期，When 冷静期结束且未撤销注销，Then 系统在承诺时限内删除或匿名化该账号的个人数据

**SEC-18 隐私政策入口**
- Given 用户处于注册流程或设置页，When 查找隐私政策，Then 可在两次点击内找到隐私政策与用户协议的完整入口

**SEC-09 申诉通道（P1）**
- Given 用户账号处于禁言或封号状态，When 用户在处置提示页提交申诉材料，Then 申诉单创建成功，用户可在设置中查看申诉进度

**SEC-16 个人信息导出（P1）**
- Given 用户在设置中申请导出个人信息，When 24 小时内已提交过一次申请，Then 系统拒绝新的申请并提示下次可申请时间

**SEC-19/20 未成年人模式（P1）**
- Given 用户已开启青少年模式，When 有非好友用户向其发送消息，Then 消息被直接拦截，不进入消息请求分区

## 6. 边界与异常场景

- **重复举报同一对象**：系统对同一举报人在短时间内针对同一目标的重复举报进行合并计数，不重复进入人工队列，避免占用审核资源。
- **恶意刷举报**：识别到某账号短时间内发起大量举报且命中率极低，触发举报权限限流，降低其举报优先级并可能触发人工核查该账号本身。
- **被举报对象已注销或消息已撤回**：举报单仍可基于举报时的快照内容（截图/存档）继续审核，避免用户通过删除/注销逃避处置。
- **弱网下举报提交失败**：客户端本地保留举报草稿，网络恢复后自动重试提交，避免用户重复操作。
- **风控误判申诉集中在特定规则**：审核团队需能追溯到具体命中的风控规则版本，便于规则调优，避免同类误判反复发生。
- **未成年人账号被举报**：涉及未成年人的举报默认提升处理优先级，加速进入人工审核。
- **数据导出请求频繁**：对同一账号的个人信息导出请求设置冷却期（如 24 小时一次），避免被用于批量爬取。
- **注销冷静期内用户后悔**：用户可在冷静期内重新登录并主动撤销注销申请，账号与数据完全恢复。
- **账号封禁期间的隐私权利**：账号被封禁不影响其提交数据导出或注销申请的权利，两类请求走独立通道处理。

## 7. 依赖关系

- 依赖 [账号与用户体系](01-account.md) 提供账号状态机（正常/禁言/封禁/注销）与登录鉴权
- 依赖 [关系链](02-relationship.md) 的黑名单与好友关系判定，作为非好友消息限制与拉黑联动的基础
- 依赖 [消息能力](03-messaging.md) 的消息撤回与消息状态机制，配合违规消息的拦截与事后处理
- 依赖 [群聊](05-group-chat.md) 的群主/管理员权限体系，支撑群组维度的举报与处置
- 依赖 [通知推送](08-notification.md) 完成举报结果、处置通知、申诉进度的触达
- 关联 [演进路线图](99-roadmap.md)：E2EE 上线后，服务端将无法直接扫描消息明文内容，届时需重新设计内容风控的实现方式（如客户端侧检测、举报后解密复核等）
