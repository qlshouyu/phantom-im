# 群聊

> 版本：v0.1 ｜ 优先级概览：P0/P1 混合 ｜ 上级文档：[PRD 总纲](README.md)

## 1. 功能概述

群聊是多人协同交流的场景，涉及比单聊更复杂的成员关系与权限体系。本分档聚焦：

1. **群的生命周期**——建群、邀请入群、退群、踢人、解散群；
2. **权限体系**——群主与管理员的角色划分、权限边界、群主转让；
3. **群内沟通效率工具**——@提醒（单人/全体）、群公告、群名片（群内昵称）；
4. **群规模治理**——MVP 阶段群成员上限 500 人，超限后的处理策略。

群聊的消息类型、消息状态、撤回等能力复用 [消息能力](03-messaging.md) 的通用规则；本文档只描述群场景下的特殊规则（如撤回权限扩展到管理员、@全体的权限限制等）。

## 2. 用户场景（User Story）

1. 作为用户，我希望从好友列表多选几位好友一键建群，以便快速拉起一次多人讨论，而不必逐个私聊转发。
2. 作为群主，我希望能任命信任的成员为管理员，以便分担群管理工作，而不必事事亲力亲为。
3. 作为普通成员，我希望在消息中@某个人后对方能收到特殊提醒，以便确保重要信息不被淹没在消息流中。
4. 作为管理员，我希望能禁言在群里刷屏或发不当内容的成员，以便维持群内讨论秩序而不必直接踢人。
5. 作为用户，我希望通过扫描群二维码或点击邀请链接加入感兴趣的群，以便不依赖群成员逐个拉人。

## 4. 关键交互流程

### 4.1 建群

1. 用户在"发起聊天"入口选择"建群"。
2. 从好友列表多选至少 2 位好友（创建者自动包含在内，共至少 3 人）。
3. 可选填写群名称（默认使用成员昵称拼接生成，如"张三、李四、王五"）。
4. 点击"创建"，服务端生成群 ID，创建者自动成为群主，所有被选好友自动成为群成员，群聊会话出现在各成员的会话列表中。
5. 群内自动插入一条系统消息："XX 创建了群聊"。

### 4.2 邀请入群与人数上限

1. 群主/管理员（或开启邀请权限后的普通成员）在群设置中点击"邀请好友"。
2. 从好友列表多选目标好友。
3. 客户端预校验：若"当前群人数 + 拟邀请人数"超过 500，禁用"确认邀请"按钮并提示"群成员已达上限，无法继续邀请"。
4. 校验通过后发起邀请，被邀请人直接加入（MVP 阶段普通群默认免验证），群内插入系统消息"XX 邀请 YY 加入了群聊"。

### 4.3 踢人与退群

1. 群主/管理员在群成员列表中选择目标成员，点击"移出群聊"。
2. 二次确认弹窗提示"确定将 XX 移出群聊？"。
3. 确认后，服务端将该成员移出群成员关系，目标用户的该群会话标记为"已被移出"，无法继续发消息但可保留查看历史记录（本地已同步部分）。
4. 群内插入系统消息"XX 被移出群聊"（不显示操作人身份，保护隐私可配置）。
5. 成员主动退群流程类似，插入系统消息"XX 退出了群聊"，群主退群前需先完成 GC-09 群主转让。

### 4.4 群主转让与管理员任命

1. 群主进入"群管理"页，选择"转让群主"。
2. 从成员列表选择目标成员，二次确认（含风险提示："转让后你将失去群主权限"）。
3. 确认后，目标成员即时成为群主，原群主降级为普通成员或管理员（由转让操作时的选项决定）。
4. 管理员任命流程：群主在成员列表选择目标成员，点击"设为管理员"，即时生效，无需目标成员确认。

### 4.5 @提醒

1. 用户在输入框输入 "@"，弹出群成员候选列表（支持拼音/名称模糊搜索）。
2. 若为群主/管理员，候选列表顶部额外展示"全体成员"选项。
3. 用户选择目标后，输入框插入 "@昵称" 标记并随消息一并发送。
4. 消息送达后，被@的成员（或全体成员，若为@全体）在 [会话列表](06-conversation.md) 中收到特殊未读提醒。

### 4.6 解散群

1. 群主在"群管理"页点击"解散群聊"。
2. 二次确认弹窗（要求输入群名称或滑动确认，防误触）。
3. 确认后，服务端将群状态标记为已解散，所有成员的群会话变为只读，输入框禁用并展示"该群聊已解散"。
4. 各成员本地已同步的历史消息保留，可继续查看与搜索，但会话不再接收新消息。

## 5. 验收标准

**GC-01**
- Given 用户在好友列表选择 3 位好友并点击"创建群聊"，When 创建成功，Then 生成一个包含创建者共 4 人的群聊会话，创建者角色为群主。

**GC-02**
- Given 一个群当前有 499 名成员，When 群主邀请 1 位好友入群，Then 邀请成功，群成员数变为 500。
- Given 一个群当前有 500 名成员，When 群主尝试邀请任意好友入群，Then 邀请入口提示"群成员已达上限，无法继续邀请"，邀请动作被阻止。

**GC-06**
- Given 用户 A 是群管理员，成员 B 是普通成员，When A 对 B 执行"移出群聊"，Then B 被成功移出，群内插入系统提示，B 端会话变为只读。
- Given 用户 A 是群管理员，成员 C 是另一位管理员，When A 尝试对 C 执行"移出群聊"，Then 操作被拒绝，客户端展示"管理员无权移出其他管理员"。

**GC-13**
- Given 用户在群消息中 @成员 B 并发送，When B 打开会话列表，Then B 对应的会话在未读数旁展示 "有人@我" 的特殊标识。

**GC-14**
- Given 普通成员在群消息输入框输入 "@"，When 弹出候选列表，Then 列表中不包含"全体成员"选项。
- Given 群主输入 "@" 并选择"全体成员"发送，When 消息送达，Then 所有群成员（无论是否开启免打扰）均在会话列表收到 @提醒特殊标识。

**GC-19**
- Given 成员在群内设置了群名片"小明"，When 其他成员查看群成员列表，Then 该成员展示为"小明"而非其账号昵称。

**GC-21**
- Given 群主修改群名称为"周末爬山群"，When 任意成员打开该群会话，Then 聊天页与会话列表标题均更新为"周末爬山群"。

**GC-24**
- Given 群主点击"解散群聊"并完成二次确认，When 解散成功，Then 所有成员的该群会话输入框被禁用并展示"该群聊已解散"，历史消息仍可查看。

## 6. 边界与异常场景

- **群名冲突**：群名称允许重复，不做唯一性校验，仅在会话列表中通过头像/最新消息辅助区分。
- **建群人数下限**：若可选好友不足 2 人（如新注册用户尚无好友），"建群"入口置灰并提示"至少邀请 2 位好友才能建群"。
- **并发踢人与退群**：成员 B 正在执行"退群"的同时，管理员对 B 发起"移出群聊"，以服务端最先处理成功的请求为准，后到达的请求返回"该成员已不在群内"，不重复插入系统消息。
- **群主离线转让**：群主转让操作要求目标成员为当前群内成员且账号状态正常（未注销/未封禁），若目标账号在转让确认瞬间被封禁，转让失败并提示重新选择。
- **管理员被取消资格后的禁言效力**：管理员对成员设置的禁言，在该管理员被群主取消管理员身份后依然有效，不自动解除，需群主或其他管理员手动解除。
- **全员禁言下的例外**：全员禁言状态下，群主与管理员仍可发言，且可正常使用 @全体（不受 GC-15 频率限制外的禁言影响）。
- **@全体频率限制触发**：管理员在 60 秒内第二次尝试发送 @全体消息，客户端在发送前拦截并提示"@全体消息发送过于频繁，请稍后再试"，倒计时展示剩余等待时间。
- **群解散后的邀请链接/二维码**：群解散后已生成的邀请链接与二维码立即失效，扫码/点击后提示"该群聊已解散"。
- **弱网下的踢人/退群指令**：操作发起后本地先展示"处理中"状态，网络恢复后重试提交；若最终失败（如群已被解散），提示具体失败原因并回滚本地状态。
- **群成员列表规模渲染**：500 人群成员列表采用分页/虚拟滚动加载，避免一次性渲染全部成员导致卡顿。
