# 应用与用户身份

> 版本：v0.2（平台化重写）｜ 优先级概览：P0 为主 ｜ 上级文档：[PRD 总纲](README.md)
>
> **v0.2 重大变更**：Phantom IM 定位调整为**即时消息开发平台（PaaS）**，对外提供 SDK 与 OpenAPI。平台不再承载 C 端账号体系——用户注册、登录凭证、隐私管理、注销均由接入方（第三方开发者）自己的用户体系承担；平台只保留全局唯一的 **Phantom ID** 作为用户身份锚点，供接入方与自有用户体系关联。v0.1 中的手机号/邮箱注册登录、验证码、隐私设置、注销冷静期等 C 端能力全部移除。

## 1. 功能概述

平台身份模型分三层：

```
开发者（控制台账号）
  └─ 应用 App（AppID / AppSecret）        —— 租户与鉴权边界
       └─ 用户（Phantom ID ↔ external_user_id）—— 消息收发的主体
```

本功能域解决三个核心问题：

1. **应用是谁**——开发者如何创建应用、获得并保管 AppID/AppSecret。
2. **用户是谁**——接入方如何把自己的用户映射为平台的 Phantom ID（导入/创建），以及 SDK 如何凭接入方签发的 UserToken 完成登录。
3. **用户长什么样、还能不能用**——平台保留的极简资料（昵称/头像/扩展字段）如何写入与展示，接入方如何禁用、恢复、删除用户。

本功能域是全平台的前置依赖：没有应用与 Phantom ID 就没有关系链、消息与多端同步。

## 2. 用户场景（User Story，开发者视角）

1. 作为一名**电商 App 开发者**，我希望在服务端调用 OpenAPI 将买家和卖家导入平台并获得 Phantom ID，以便为订单会话提供买卖双方在线沟通能力。
2. 作为一名**开发者**，我希望我的用户无需再注册一套 IM 账号，App 内使用我服务端签发的 UserToken 直接建立 IM 连接，登录体验对用户完全透明。
3. 作为一名**开发者**，我希望用户在我的体系里修改昵称或头像时，能同步到 IM 的会话列表与群成员展示。
4. 作为一名**开发者**，当用户在我的体系中注销或被封禁时，我希望能立即禁用其 IM 能力并踢下线，避免僵尸账号继续收发消息。
5. 作为一名**开发者**，我希望按应用开启/关闭关系链托管、已读反馈、阅后即焚等能力，让 IM 行为匹配我的产品形态（客服工具不需要好友关系，私密社交需要阅后即焚）。
6. 作为一名**安全负责人**，我怀疑 AppSecret 泄漏时，希望能轮换秘钥且线上用户不因此集体掉线。

## 3. 功能需求清单

| 需求编号 | 需求描述 | 优先级 |
|---------|---------|--------|
| AC-01 | 开发者可在控制台创建应用，系统分配全局唯一 AppID 并生成 AppSecret；AppSecret 仅创建时明文展示一次，此后只可轮换不可查看 | P0 |
| AC-02 | OpenAPI 创建/导入用户：入参为接入方用户标识 `external_user_id`，平台分配**全局唯一 Phantom ID** 并返回；同一 `(app_id, external_user_id)` 重复调用幂等返回既有 Phantom ID | P0 |
| AC-03 | UserToken 由接入方服务端使用 AppSecret 按平台规范（JWT HS256）**本地签发**，平台仅验签，登录不回调接入方服务 | P0 |
| AC-04 | SDK 以 `(AppID, Phantom ID, UserToken)` 建立长连接完成登录；UserToken 过期时 SDK 回调宿主 App 获取新 Token 后自动重连 | P0 |
| AC-05 | 平台保留用户极简资料：昵称、头像 URL、ext 扩展键值对；可经 OpenAPI（服务端）或 SDK（客户端）写入，SDK 写入口可按应用配置禁用 | P0 |
| AC-06 | OpenAPI 支持禁用/恢复用户：禁用后立即踢下线（全设备）且拒绝再登录，消息发往该用户正常入库、待恢复后同步 | P0 |
| AC-07 | OpenAPI 支持删除用户：解除 `external_user_id` 映射并释放，历史消息中该用户展示为"已注销用户"快照；Phantom ID 永不复用 | P0 |
| AC-08 | 应用级功能配置：关系链托管、已读反馈、阅后即焚（含 TTL）等能力按应用维度开关，认证握手时随 AuthResp 下发客户端 | P0 |
| AC-09 | AppSecret 支持轮换：轮换后进入宽限期（≤7 天），期内新旧秘钥签发的 UserToken 均可验签通过，宽限期满旧秘钥失效 | P1 |
| AC-10 | OpenAPI 支持强制下线指定用户的全部或指定设备连接 | P1 |
| AC-11 | 昵称/头像写入经内容安全审核，违规拒绝写入并返回明确错误码（审核规则见 [安全与合规](10-security.md)） | P1 |

## 4. 关键交互流程

### 4.1 应用创建（控制台）

1. 开发者注册/登录开发者控制台（控制台自身账号体系不在本 PRD 范围）。
2. 创建应用，填写应用名称、场景说明。
3. 系统分配 AppID，生成 AppSecret 并**仅此一次**明文展示，开发者确认已保存后不可再查看。
4. 应用创建后默认关闭关系链托管、已读反馈、阅后即焚，开发者按需在控制台开启（AC-08）。

### 4.2 用户导入与首次登录

1. 接入方服务端调用 `POST /openapi/users`，传 `external_user_id`（及可选昵称/头像）。
2. 平台校验 `(app_id, external_user_id)` 映射：不存在则创建用户、分配 Phantom ID；已存在则幂等返回既有 Phantom ID（AC-02）。
3. 接入方服务端用 AppSecret 按 4.3 规范签发 UserToken，连同 Phantom ID 下发给自己的客户端。
4. 客户端 SDK 携 `(AppID, Phantom ID, UserToken)` 发起长连接认证（协议 AuthReq），平台本地验签通过即登录成功，登记多端在线路由表。

### 4.3 UserToken 签发规范

1. 格式为 JWT（HS256，签名秘钥 = AppSecret），claims 至少包含：`app_id`、`user_id`（Phantom ID）、`iat`、`exp`。
2. 有效期由接入方自定，平台建议 ≤ 7 天并强制上限 30 天；`exp` 超出上限的 Token 验签直接拒绝。
3. 平台验签规则：签名有效、未过期、`app_id` 存在且未停用、`user_id` 属于该应用且未被禁用。
4. Token 过期处理：长连接存量连接不因过期中断，下次重连时校验；重连被拒（错误码 2001）时 SDK 回调宿主 App 请求新 Token，取回后自动重连。

### 4.4 用户禁用与删除

1. 禁用：`POST /openapi/users/{phantom_id}/disable` → 平台立即断开该用户全部设备连接（KickPush），后续登录验签直接拒绝；期间他人发来的消息正常入库，恢复后按同步协议补齐。
2. 恢复：`POST /openapi/users/{phantom_id}/enable` → 恢复登录能力。
3. 删除：`DELETE /openapi/users/{phantom_id}` → 解除并释放 `external_user_id` 映射（可被重新注册为新用户），该 Phantom ID 永不复用；历史消息与群成员列表中展示"已注销用户"占位快照。

## 5. 验收标准

**AC-01 应用创建**
- Given 开发者在控制台创建应用成功，When 查看应用详情，Then 可见 AppID 但无法再次查看 AppSecret 明文，仅提供"轮换"操作。

**AC-02 用户导入幂等**
- Given 接入方已用 `external_user_id=U1001` 创建过用户并获得 Phantom ID P1，When 再次以 `U1001` 调用创建接口，Then 返回相同的 P1，不产生新用户。

**AC-03/04 UserToken 登录**
- Given 接入方服务端用正确 AppSecret 签发未过期 UserToken，When SDK 携 (AppID, Phantom ID, UserToken) 发起认证，Then 登录成功且平台未向接入方服务端发起任何回调。
- Given UserToken 已过期，When SDK 重连认证，Then 返回错误码 2001，SDK 触发宿主 App 的 Token 刷新回调，取得新 Token 后重连成功。

**AC-05 资料写入与展示**
- Given 接入方经 OpenAPI 将用户昵称改为新值，When 其他用户拉取会话列表或群成员，Then 展示新昵称（资料变更经同步事件下发在线端）。

**AC-06 禁用即时生效**
- Given 用户 P1 在两台设备在线，When 接入方调用禁用接口成功，Then P1 两台设备均收到踢下线并无法重新登录；期间他人向 P1 发送的消息在 P1 恢复后可完整同步。

**AC-07 删除后的展示**
- Given 用户 P1 被删除，When 其他成员查看含 P1 历史发言的群聊，Then P1 的消息仍可见，发送者展示为"已注销用户"及默认头像。

**AC-09 秘钥轮换宽限**
- Given 应用完成 AppSecret 轮换且处于宽限期，When 旧秘钥签发的未过期 UserToken 发起登录，Then 验签通过；宽限期满后同一 Token 登录被拒绝。

**AC-12 OpenAPI 鉴权**
- Given 调用方使用错误的 AppSecret 对请求签名，When 调用任一 OpenAPI，Then 返回鉴权失败，且同一 AppID 连续鉴权失败触发限频保护。

## 6. 边界与异常场景

- **C 端能力归属**：注册、登录凭证（密码/验证码）、找回、隐私设置（谁能找到我）、账号注销发起，全部由接入方用户体系承担；平台侧仅暴露"禁用/删除"OpenAPI 供接入方联动其注销/封禁流程。
- **`external_user_id` 不可变更**：与 Phantom ID 的映射一经建立不支持改绑；接入方用户标识变更应视为删除旧用户 + 创建新用户。
- **AppSecret 泄漏应急**：立即轮换并将宽限期设为 0（控制台高危操作，需二次确认）——旧秘钥签发的全部 UserToken 即刻失效，线上用户在下次重连时统一走 Token 刷新回调，短暂重连风暴由网关限频消化。
- **同一用户多应用**：Phantom ID 归属于单一应用，跨应用的同一自然人是两个独立用户；平台不提供跨应用身份打通。
- **未导入用户被指定为消息接收方**：返回"用户不存在"错误（3001），不隐式创建用户，避免脏数据。
- **资料审核不通过**：写入被拒绝并返回错误码，保留原资料；不阻断消息收发主流程。
- **极限值**：`external_user_id` 长度 1-64（字母/数字/`_`/`-`/`@`/`.`）；昵称 1-20 字符（含 emoji 按 2 字符计）；ext 扩展 ≤ 16 个键、单值 ≤ 512 字节；头像 URL ≤ 1024 字节。
- **禁用与群的关系**：被禁用用户不自动退群，群成员列表照常展示；被删除用户由系统自动退出其所有群。
