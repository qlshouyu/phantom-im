# 关系链

> 版本：v0.1 ｜ 优先级概览：P0 为主，分组管理与好友上限为 P1 ｜ 上级文档：[PRD 总纲](README.md)
>
> ⚠️ **平台化待适配**（见 [01 应用与用户身份 v0.2](01-account.md)）：关系链降级为**应用级可选托管能力**（控制台开关，默认关闭）；依赖 C 端账号体系的部分失效——手机号/二维码搜索加友、"谁能添加我"隐私设置由接入方自行实现，托管模式下平台仅保留好友/黑名单关系的存储、校验与同步。

## 1. 功能概述

关系链功能域解决"用户之间如何建立、维护、终止社交连接"的问题，是单聊与群聊得以发生的社交基础。核心能力包括：多途径添加好友、好友申请与验证机制、好友列表的组织（备注、分组），以及关系的终止形态（删除好友、拉黑）。

关系链的设计原则是**用户对自己的社交边界拥有完全控制权**：谁能找到我（见 [账号与用户体系](01-account.md) 的隐私设置）、谁能加我为好友、加了之后如何称呼和归类、以及何时终止关系，全流程用户可自主决定，系统不做强制撮合。

## 2. 用户场景（User Story）

1. 作为一名**用户**，我希望通过对方的 Phantom ID 精确搜索并发起好友申请，以便添加线下认识但没有存手机号的朋友。
2. 作为一名**用户**，我希望通过扫描对方的二维码名片添加好友，以便在线下见面场景中快速加好友。
3. 作为一名**群成员**，我希望在群聊中点击某位成员的头像发起加好友申请，以便把群里认识的人沉淀为私人好友。
4. 作为一名**用户**，我希望给好友设置备注和分组，以便在好友列表庞大时快速找到"家人""同事"等特定关系的人。
5. 作为一名**用户**，我希望能拉黑骚扰我的人，以便彻底屏蔽对方的消息和好友申请，不再受到打扰。
6. 作为一名**用户**，我希望删除一个不再联系的好友，以便清理好友列表，同时不希望这个操作打扰到对方。

## 4. 关键交互流程

### 4.1 ID 搜索添加好友

1. 用户在"添加好友"页输入对方 Phantom ID 或手机号，点击搜索。
2. 系统按 [账号与用户体系](01-account.md) 中 AC-12 的隐私开关过滤搜索结果：若对方关闭对应查找方式，返回"未找到该用户"。
3. 搜索命中后展示对方基础资料卡片（头像、昵称、ID），用户点击"添加好友"。
4. 若对方隐私设置为"所有人可加"，直接建立好友关系；若为"需验证"，进入 4.2 申请流程；若为"拒绝所有人"，按钮置灰并提示。

### 4.2 好友申请与验证

1. 申请发起方填写验证消息（可选），提交申请。
2. 接收方在"好友申请"列表页看到新申请，含发起方资料与验证消息、申请来源（搜索/二维码/群聊）。
3. 接收方选择：
   - **通过**：双方建立好友关系，各自好友列表新增对方，会话列表生成一条"你们已成为好友"系统提示。
   - **拒绝**：申请被标记为已拒绝，发起方申请列表同步更新状态，不触发通知打扰接收方。
   - **忽略**：申请保留在列表中不做处理，发起方看不到明确拒绝反馈。
4. 若开启 REL-08 自动通过，申请提交后立即视为"通过"，跳过人工审核步骤。

### 4.3 群聊内添加好友

1. 用户在群聊成员列表点击某成员头像，进入其资料卡片。
2. 若该成员非当前用户好友，展示"加好友"按钮；若群主/管理员关闭了"允许群成员互加好友"，按钮隐藏并提示。
3. 后续流程与 4.2 一致，申请来源标记为"来自群聊《群名》"。

### 4.4 备注与分组管理

1. 用户在好友资料页点击"设置备注"，输入备注名并保存，即时生效，仅本人可见。
2. 用户在好友列表页选择"分组管理"，可新建分组、重命名分组、拖拽好友到不同分组。
3. 好友可同时归属多个分组；未分组好友归入默认的"我的好友"分组。

### 4.5 删除好友与拉黑

1. 用户在好友资料页选择"删除好友"，二次确认后执行：从自己的好友列表移除对方，会话保留但标记为"非好友"状态，对方好友列表中该用户不受影响（对方仍视用户为好友，直至对方也执行删除）。
2. 用户选择"拉黑"，二次确认后执行：双向好友关系解除（若原为好友），对方进入用户黑名单；此后对方无法向用户发起好友申请、发送消息、查看资料。
3. 用户在黑名单管理页选择"解除拉黑"，对方恢复为"陌生人"状态（非自动恢复好友关系，需重新走添加流程）。

## 5. 验收标准

**REL-01 ID 搜索添加好友**
- Given 用户输入一个存在且允许被 ID 搜索到的 Phantom ID，When 点击搜索，Then 系统返回该用户的资料卡片；When 点击"添加好友"，Then 按对方隐私设置进入直接添加或申请流程。

**REL-02 手机号搜索受隐私约束**
- Given 目标用户已关闭"通过手机号找到我"，When 发起方使用其手机号搜索，Then 搜索结果为空，不泄露该手机号对应任何账号信息。

**REL-03 二维码添加好友**
- Given 用户扫描一张有效的好友二维码，When 扫描成功，Then 系统展示对方资料卡片并可发起添加，流程与 ID 搜索添加一致。

**REL-04 群内加好友**
- Given 用户与群成员均在同一未关闭互加权限的群聊中，When 用户点击该成员头像并发起好友申请，Then 申请成功发出，申请来源标记为该群聊。

**REL-06 好友申请处理**
- Given 接收方收到一条好友申请，When 点击"通过"，Then 双方互相出现在对方好友列表中，且会话列表生成系统提示消息；When 点击"拒绝"，Then 该申请状态变为已拒绝，接收方好友列表不发生变化。

**REL-07 申请列表未读提醒**
- Given 用户收到一条新的好友申请，When 未打开申请列表页，Then "好友申请"入口显示未读角标；When 用户打开该页面，Then 角标清除。

**REL-09 好友列表排序**
- Given 用户好友列表包含多个联系人，When 用户打开好友列表页，Then 好友按姓名拼音首字母升序展示，置顶好友固定显示在列表最前。

**REL-10 备注生效**
- Given 用户为好友"张三"设置备注"财务-老王"，When 保存成功，Then 该好友在会话列表、聊天页标题、@提及等所有展示位置均显示为"财务-老王"而非其原昵称。

**REL-12 删除好友单向性**
- Given 用户 A 删除好友 B，When 删除操作完成，Then A 的好友列表中不再包含 B，且 B 未收到任何通知；B 的好友列表中仍保留 A（直至 B 也主动删除）。

**REL-13 拉黑生效**
- Given 用户 A 拉黑用户 B，When 拉黑操作完成，Then B 无法再向 A 发送消息（发送时收到"消息发送失败，对方拒绝接收"提示），B 无法查看 A 的完整资料，也无法向 A 发起好友申请。

**REL-14 解除拉黑**
- Given 用户 A 在黑名单管理页选择解除拉黑用户 B，When 操作完成，Then B 从黑名单列表移除，B 恢复为可被重新搜索添加的陌生人状态，双方原好友关系不自动恢复。

**REL-05 申请附加验证消息**
- Given 用户发起好友申请时填写了验证消息"我们是XX大学校友"，When 申请提交成功，Then 接收方在申请列表中能看到该验证消息内容，用于辅助判断是否通过。

**REL-08 自动通过好友申请**
- Given 用户已开启"无需验证，自动通过好友申请"，When 有其他用户向其发起好友申请，Then 申请无需人工审核，立即建立双向好友关系，双方好友列表同步更新。

## 6. 边界与异常场景

- **重复发起好友申请**：若已存在一条待处理申请，用户再次发起时不重复创建新申请，提示"你已发送过好友申请，请等待对方处理"。
- **对已是好友的用户再次发起申请**：系统直接提示"你们已经是好友"，不进入申请流程。
- **申请发起后对方修改了隐私设置**：以申请发起时刻的规则为准，已发出的申请不因对方后续调整隐私设置而失效。
- **二维码过期或被刷新后使用旧码**：扫描后提示"该二维码已失效，请让对方刷新后重新出示"。
- **群解散或用户退群后处理群内发起的待处理申请**：申请本身不受影响，仍可正常审核通过，因关系链独立于群成员关系存在。
- **同时来自多端的重复操作**：例如手机端与桌面端同时点击"通过"同一好友申请，服务端以先到者为准处理，后到请求返回"该申请已被处理"提示，客户端据此更新本地状态，不报错阻断。
- **拉黑后原有会话记录处理**：拉黑不清除已有聊天记录，双方本地仍可查看历史消息，仅阻断新消息与好友申请。
- **达到好友数量上限（REL-15）**：新申请尝试添加会被系统直接拒绝，前端提示"好友数量已达上限，请先精简好友列表"，已有好友关系不受影响。
- **弱网下添加/删除操作**：客户端本地先做乐观更新（如立即从列表移除待删除好友），若服务端确认失败则回滚状态并提示"操作失败，请重试"。
- **黑名单与好友关系互斥**：一个用户不能同时处于"好友"和"黑名单"状态，拉黑操作会自动解除好友关系。
- **分组被删除时好友的归属**：删除一个自定义分组不会删除好友本身，该分组下的好友自动归入默认的"我的好友"分组。
- **验证消息含违规内容**：好友申请中的验证消息与所有用户输入内容一样需经内容安全审核，审核不通过的申请仍可送达但验证消息以"[内容不合规，已隐藏]"替代展示。
- **好友双向删除的对称性**：若 B 也执行删除好友操作，则双方关系彻底解除，会话中"非好友"提示同步消失，双方均需重新走添加流程才能恢复。
- **申请长期未处理**：好友申请无自动过期机制，长期保留在接收方申请列表中，由接收方自行决定处理时机，避免因超时误伤慢回复用户的正常社交诉求。

## 7. 依赖关系

- 好友搜索与添加的可见性边界由 [账号与用户体系](01-account.md) 中的隐私设置（AC-11、AC-12）决定。
- 好友申请消息、系统提示消息在产品层面复用 [消息能力](03-messaging.md) 定义的消息类型与展示原则。
- 好友关系是发起 [单聊](04-direct-chat.md) 的默认前置条件（非好友受限交互规则见该分档）。
- 群聊内加好友的权限开关（是否允许成员互加）由 [群聊](05-group-chat.md) 的群设置管理。
- 骚扰行为的举报处理与黑名单的风控联动，详见 [安全与合规](10-security.md)。
