# Phantom IM 产品需求文档（PRD）总纲

> 版本：v0.1 ｜ 状态：草案 ｜ 最后更新：2026-08-06

## 1. 产品愿景

Phantom IM 是一款**全平台通用社交即时通讯产品**，覆盖 iOS、Android、Web 与桌面端（Windows/macOS）。产品理念是：**把基础聊天体验做深做透**——消息可靠必达、多端无缝同步、交互简洁流畅，而不是在 MVP 阶段堆砌功能。

一句话定位：**随时随地、任意设备，与你关心的人可靠地保持联系。**

## 2. 目标用户

| 用户群 | 特征 | 核心诉求 |
|--------|------|----------|
| 主流社交用户 | 日常与好友/家人保持联系 | 简单易用、消息可靠、不丢消息 |
| 多设备工作者 | 手机 + 电脑并用，频繁切换设备 | 多端同步无缝，任意设备可查历史消息 |
| 兴趣社群成员 | 参与多个群组讨论 | 群聊管理有序、@提醒不遗漏、可静音免打扰 |

## 3. 核心场景

1. **单聊**：用户与好友一对一交流，发送文本、图片、语音、文件等多种消息，实时看到对方输入状态与已读回执。
2. **群聊**：用户创建或加入群组，与多人协同交流，通过 @提醒、群公告、管理员机制保持沟通有序。
3. **多端切换**：用户在手机上聊到一半，坐到电脑前打开桌面端，会话、消息、未读状态完全一致，无缝续聊。
4. **离线可达**：用户离线时通过系统推送获知新消息，重新上线后自动补齐离线期间的全部消息。

## 4. MVP 边界

**纳入 MVP（本 PRD 文档集详细展开）：**

- 账号体系（注册登录、个人资料、隐私设置）
- 关系链（好友申请、备注分组、黑名单）
- 消息能力（富消息类型、消息状态、撤回、转发、引用）
- 单聊与群聊
- 会话列表（置顶、免打扰、未读数、草稿）
- 多端同步与消息漫游（全平台核心 P0 能力）
- 离线通知推送
- 搜索（联系人、群、聊天记录）
- 安全与合规（举报、封禁、内容治理、数据隐私）

**不纳入 MVP（见 [演进路线图](99-roadmap.md)）：**

- 音视频通话（1v1 / 群组）
- 动态 / 朋友圈
- 端到端加密（E2EE）
- 消息云备份与迁移、开放平台等

## 5. 优先级定义

| 级别 | 定义 | 发布要求 |
|------|------|----------|
| **P0** | 核心必备，缺失则产品不可用或体验不完整 | MVP 首版必须交付 |
| **P1** | 重要增强，显著提升体验但可短期缺席 | MVP 后 1-2 个迭代内交付 |
| **P2** | 锦上添花或长线功能 | 进入路线图，按阶段规划 |

### 分档统一模板

每篇分档遵循相同结构，便于查阅与评审：

1. **功能概述** — 该功能域解决什么问题
2. **用户场景（User Story）** — 以用户视角描述典型使用场景
3. **功能需求清单** — 逐条需求，标注 P0/P1/P2 优先级
4. **关键交互流程** — 主要操作路径的步骤化描述
5. **验收标准** — GWT 格式（Given/When/Then）
6. **边界与异常场景** — 弱网、冲突、极限值等
7. **依赖关系** — 与其他功能域分档的关联链接

## 7. 全局非功能性原则

以下原则贯穿所有功能域，各分档不再重复展开：

- **消息可靠性**：消息不丢、不重、不乱序是底线；客户端与服务端均需幂等去重。
- **全平台一致性**：四端（iOS/Android/Web/桌面）功能对齐，交互遵循各平台规范但信息架构一致。
- **弱网可用**：弱网/断网下可查看本地历史，恢复后自动重发与补齐。
- **渐进式披露**：界面与文档都遵循"先总后分"——默认呈现最常用能力，高级能力按需展开。

## 8. 术语表

| 术语 | 定义 |
|------|------|
| 会话（Conversation） | 用户与某个好友或群组的消息聚合单元，展示在会话列表中 |
| 消息漫游 | 历史消息存储于云端，任意设备登录后可拉取查看 |
| 已读回执 | 消息被接收方阅读后，发送方可见"已读"状态 |
| 关系链 | 用户之间的好友关系及其衍生数据（备注、分组、黑名单） |
| GWT | Given/When/Then，验收标准的结构化描述格式 |
