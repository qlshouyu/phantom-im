# 会话列表

> 版本：v0.1 ｜ 优先级概览：P0 为主 ｜ 上级文档：[PRD 总纲](README.md)

## 1. 功能概述

会话列表是用户打开 Phantom IM 后看到的首屏入口，聚合展示用户所有的单聊与群聊会话。本分档聚焦：

1. **会话的生成与排序**——新消息如何驱动会话产生与排序变化；
2. **会话管理动作**——置顶、免打扰、删除，及其对未读数/角标展示的影响；
3. **草稿**——用户输入未发送内容的留存与提示；
4. **多端一致性**——会话列表状态（置顶/免打扰/删除/草稿）在多端间的同步联动。

会话列表不产生消息本身，只是消息、好友、群聊等能力在列表层面的聚合视图；具体消息内容规则见 [消息能力](03-messaging.md)，单聊/群聊场景见 [单聊](04-direct-chat.md)、[群聊](05-group-chat.md)。

## 2. 用户场景（User Story）

1. 作为用户，我希望打开 App 首屏看到的会话按最新消息时间倒序排列，以便第一时间看到最近有互动的人和群。
2. 作为用户，我希望把常用的几个会话置顶，以便不被其他新消息淹没，随时能快速找到。
3. 作为用户，我希望对活跃但不重要的群开启免打扰，以便既不错过消息又不被频繁打扰。
4. 作为用户，我希望看到未读消息数量与"有人@我"的特殊提示区分开，以便优先处理真正需要我回应的消息。
5. 作为用户，我希望输入到一半没发送的内容离开会话后不会丢失，并在列表上有所提示，以便回来后能继续编辑。

## 4. 关键交互流程

### 4.1 新消息驱动排序更新

1. 客户端接收到一条新消息（或多端同步事件）。
2. 若该消息所属会话已存在于本地列表：更新该会话的预览文本、时间戳、未读数，并将其移动到非置顶区域的最顶部。
3. 若该会话此前被删除（不在本地列表中）：以该消息为触发，重新生成会话条目，插入到列表顶部。
4. 若该会话被置顶：预览文本、时间戳、未读数同样更新，但会话位置保持在置顶区域内，不因新消息改变置顶区域内的排序（置顶区域仅按 CV-05 的置顶时间排序）。

### 4.2 置顶/取消置顶

1. 用户在会话列表长按（或左滑/右键）目标会话，选择"置顶"。
2. 客户端立即将该会话移动到置顶区域顶部（乐观更新），同时向服务端提交置顶状态变更。
3. 服务端确认后，变更同步至用户的其他在线设备（见 4.5）。
4. 取消置顶操作对称：会话按其最新消息时间回归普通区域对应位置。

### 4.3 免打扰设置

1. 用户在会话列表或聊天页内进入"会话设置"，开启"消息免打扰"。
2. 客户端更新本地状态：后续该会话的推送通知与提示音被抑制，未读角标切换为灰色圆点样式（CV-09）。
3. 若该会话为群聊且存在"有人@我"的未读消息，@提醒标识不受免打扰影响，仍需醒目展示（CV-11）。

### 4.4 草稿的产生与消费

1. 用户在会话输入框输入内容，未点击发送。
2. 用户返回会话列表、切换到其他会话或将 App 切至后台。
3. 客户端在离开该会话页面时，将输入框当前内容保存为本地草稿（并异步同步至服务端草稿存储，用于跨端展示）。
4. 会话列表中该会话的预览文本区域切换为"[草稿] + 内容摘要（截断展示，如前 20 字）"。
5. 用户再次进入该会话，客户端自动将草稿内容回填至输入框，光标定位到末尾。
6. 用户完成编辑并点击发送，消息发出后立即清除该会话的草稿（本地与服务端同步清除）。

### 4.5 删除会话与多端同步

1. 用户对某会话执行"删除"。
2. 客户端立即从本地列表移除该会话（乐观更新），并向服务端提交"删除会话"事件（仅删除会话-用户维度的可见性记录，不触碰消息记录本身）。
3. 服务端将该删除事件同步至用户的其他在线设备，其他设备同步移除该会话条目。
4. 后续若该会话收到新消息，各设备依据 4.1 步骤 3 重新生成该会话条目。

## 5. 验收标准

**CV-01 / CV-02**
- Given 用户有会话 A（最新消息 10:00）与会话 B（最新消息 10:05），When 用户打开会话列表，Then 会话 B 排在会话 A 之上。
- Given 会话 A 排在会话 B 之下，When 会话 A 收到一条新消息，Then 会话 A 立即上浮至会话 B 之上，预览文本更新为新消息摘要。

**CV-04 / CV-05 / CV-06**
- Given 用户将会话 C 设为置顶，When 用户返回会话列表，Then 会话 C 展示在列表最上方的置顶区域。
- Given 用户先置顶会话 C，再置顶会话 D，When 查看列表，Then 会话 D 排在会话 C 之上（后置顶的在上）。
- Given 会话 C 处于置顶状态，When 用户取消置顶，Then 会话 C 离开置顶区域，按其最新消息时间回归普通排序位置。

**CV-07 ~ CV-10**
- Given 用户对群聊 G 开启免打扰，When 群 G 收到 5 条新消息，Then 会话列表中 G 的角标展示为灰色圆点，不显示数字"5"，且不触发系统通知。
- Given 用户未对单聊 F 开启免打扰，When F 收到 3 条新消息，Then 会话列表中 F 的角标展示红色数字"3"。
- Given 单聊 F 累计未读消息达到 105 条，When 查看会话列表，Then 角标展示"99+"。

**CV-12 ~ CV-15**
- Given 用户在会话 E 输入框输入"晚上一起吃饭"但未发送，When 用户返回会话列表，Then 会话 E 的预览文本展示为"[草稿] 晚上一起吃饭"。
- Given 会话 E 存在上述草稿，When 用户再次进入会话 E，Then 输入框自动填充"晚上一起吃饭"。
- Given 用户在会话 E 将草稿内容发送出去，When 发送成功，Then 会话列表中会话 E 的草稿标识消失，预览文本更新为该消息摘要。

**CV-16 / CV-17**
- Given 用户删除与好友 H 的会话，When 操作完成，Then 该会话从列表消失，但用户仍可在与 H 的聊天页中查看历史消息（通过重新进入会话入口，如从好友资料卡"发消息"）。
- Given 会话已被删除，When 好友 H 发来一条新消息，Then 会话重新出现在列表中，展示为最新消息。

**CV-18**
- Given 用户在手机端将会话 A 设为置顶，When 用户切换到已登录的桌面端，Then 桌面端会话列表中 A 同样展示在置顶区域。
- Given 用户在手机端对会话 B 开启免打扰，When 用户切换到已登录的 Web 端，Then Web 端会话列表中 B 的角标同样展示为灰色圆点样式。

**CV-19 / CV-21**
- Given 会话 F 存在 8 条未读消息，When 用户对会话 F 执行"标记已读"，Then 角标消失，未读数归零。
- Given 用户有会话 F（非免打扰，未读 3）与会话 G（免打扰，未读 20），When 查看 App 图标角标，Then 角标数字为 3，不含会话 G 的未读数。

## 6. 边界与异常场景

- **同一时间戳消息的排序稳定性**：多条消息服务端时间戳相同（如批量补发离线消息）时，以消息的服务端自增序列号（seq）作为排序次要依据，保证多端渲染顺序一致。
- **草稿多端冲突**：用户在手机端输入草稿未发送，随后在桌面端对同一会话输入了不同的草稿内容，客户端以"最后编辑时间戳较新"的草稿为准同步覆盖，避免两端草稿互相覆盖丢失后来者内容；若两端编辑时间戳完全一致（极小概率），以最后一次同步成功的写入为准。
- **弱网下的草稿同步**：草稿的服务端同步为异步操作，本地保存优先生效；若同步失败，草稿仍在本地设备可用，仅无法跨端展示，网络恢复后自动重试同步。
- **免打扰群的@提醒与角标共存**：群聊开启免打扰且存在他人@我的未读消息时，角标同时展示灰色圆点（普通未读）与红色"@"标识（特殊提醒），二者不互相覆盖。
- **置顶数量上限**：置顶会话数量不设硬性上限，但当置顶会话超过一屏（如 10 个）时，置顶区域内部支持独立滚动，不影响普通会话区域的可见性。
- **删除会话与免打扰/置顶状态的关系**：会话被删除后，其置顶/免打扰状态一并清除；若会话因收到新消息重新生成，视为全新会话，默认不置顶、不免打扰，需用户重新设置。
- **草稿内容超长**：草稿预览摘要按前 20 个字符截断并追加省略号，完整内容仍保存，不因预览截断而丢失。
- **多端同时删除与新消息到达的竞态**：设备 A 正在提交"删除会话"请求的同时，设备 B（或服务端）收到该会话的新消息，服务端按事件到达先后顺序处理；若删除请求先处理完成，随后的新消息事件按 4.1 步骤 3 重新生成会话，最终该会话对用户可见，不会因删除请求"追上"新消息而导致会话丢失。
- **未读数与实际消息数不一致的兜底**：本地未读计数与服务端计数出现偏差时（如客户端异常退出未正确提交已读回执），以服务端下一次同步返回的权威未读数为准，覆盖本地计数。
- **应用长期未启动后的排序恢复**：用户超过设置的离线周期（如 30 天）未打开 App，重新登录后会话列表按服务端保留的最新消息时间与置顶状态一次性重建，不逐条重放历史事件动画。
- **会话列表极限长度**：用户会话总数达到较大规模（如超过 1000 个）时，列表采用分页/懒加载，避免首屏加载耗时过长；搜索历史会话入口见 [搜索](09-search.md)。
- **草稿与已发送消息的时序竞态**：用户在会话 E 编辑草稿期间，好友恰好发来一条新消息，草稿提示与新消息预览需分区展示（草稿提示优先展示在预览文本位置，新消息仅驱动时间戳与排序更新，不覆盖草稿提示文案），避免用户误以为草稿已丢失。
- **免打扰全局开关与单会话免打扰的叠加**：若用户在系统设置中开启了全局免打扰（见 [通知推送](08-notification.md)），单会话级别的免打扰状态仍独立保存，全局免打扰关闭后各会话恢复各自原有的免打扰设置，不被全局开关重置。
- **群解散/被移出群后会话的处理**：群聊被解散或用户被移出群聊后，对应会话保留在列表中并转为只读（不可再发送消息），不自动删除，规则与 [群聊](05-group-chat.md) 中的解散/踢人流程保持一致。
- **时区与时间展示**：会话列表的时间戳按用户设备本地时区展示（今天显示"时:分"，昨天显示"昨天"，更早显示"月/日"），排序逻辑始终基于服务端 UTC 时间戳，不受本地时区显示格式影响。
