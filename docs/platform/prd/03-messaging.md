# 消息能力

> 版本：v0.1 ｜ 优先级概览：P0 为主，位置/名片消息为 P1 ｜ 上级文档：[PRD 总纲](README.md)

## 1. 功能概述

消息能力是贯穿单聊与群聊的**横切基础域**，定义"一条消息从产生到最终呈现"所需的全部产品规则：消息可以是什么形态（消息类型）、消息在生命周期中处于什么状态（状态机）、消息发出后还能做什么（撤回/转发/引用/删除），以及多条消息之间如何排列、如何避免重复展示（时序与去重原则）。

本文档不区分单聊/群聊场景（场景化差异见 [单聊](04-direct-chat.md)、[群聊](05-group-chat.md)），只定义消息本身的通用产品规则，是全局非功能性原则中"消息不丢、不重、不乱序"的具体产品化落地。

## 2. 用户场景（User Story）

1. 作为一名**用户**，我希望能发送文本、图片、语音、视频、文件等多种类型的消息，以便根据场景选择最合适的表达方式。
2. 作为一名**用户**，我希望清楚看到我发的消息是"发送中""已送达"还是"对方已读"，以便判断是否需要换个方式联系对方。
3. 作为一名**用户**，我希望在发错消息后的 2 分钟内能撤回，以便及时纠正误发内容。
4. 作为一名**用户**，我希望能把一条消息转发给其他好友或群聊，以便快速分享有价值的信息而无需重新输入。
5. 作为一名**用户**，我希望在回复较早的一条消息时能引用原文，以便让对方清楚我在回应哪句话，避免歧义。
6. 作为一名**弱网环境下的用户**，我希望网络恢复后此前发送失败的消息能一键重发，且不会因为断线重连而看到重复的消息。

## 4. 关键交互流程

### 4.1 发送消息（含状态流转）

1. 用户在输入框编辑内容（文本/选取媒体文件）并点击发送。
2. 客户端立即在聊天页展示该消息，状态标记为"发送中"，同时生成 clientMsgId 并加入本地发送队列。
3. 客户端将消息上传/提交至服务端：
   - 媒体类消息（图片/语音/视频/文件）先上传至存储服务，成功后再提交消息元数据。
   - 服务端接收成功后返回全局唯一 serverMsgId 与服务端时间戳，客户端更新消息状态为"已发送"。
4. 消息投递至接收方在线设备后，服务端更新状态为"已送达"，发送方看到状态更新。
5. 接收方在聊天页实际打开并展示该消息后，触发已读回执，发送方看到状态更新为"已读"。
6. 若步骤 3-4 任一环节失败（网络中断、上传失败、服务端拒绝），消息状态置为"失败"，展示重发图标。

### 4.2 撤回消息

1. 用户长按自己发出的一条消息，若发送时间在 2 分钟内，弹出的操作菜单包含"撤回"选项。
2. 用户点击撤回，客户端本地立即将该消息替换为撤回提示占位，同时向服务端提交撤回请求。
3. 服务端校验时间窗口与消息归属，校验通过后向该会话所有在线成员（含接收方及发送方其他登录设备）广播撤回事件。
4. 各端收到撤回事件后，将对应 serverMsgId 的消息替换为"XX撤回了一条消息"提示；超过 2 分钟的撤回请求被服务端拒绝，客户端提示"超过可撤回时间"。

### 4.3 转发消息

1. 用户长按一条消息选择"转发"，或进入多选模式勾选多条消息后选择"合并转发"。
2. 单条转发：用户选择一个或多个目标会话，消息作为新的独立消息发送至每个目标会话，保留原始消息类型与内容。
3. 合并转发：客户端将勾选的多条消息打包为一张"聊天记录"卡片消息，接收方点击卡片可展开查看完整的原始消息列表（含各消息原发送人与时间）。

### 4.4 引用回复

1. 用户长按一条消息选择"回复"，输入框上方展示被引用消息的发送人昵称与内容摘要（媒体消息展示类型标签，如"[图片]"）。
2. 用户输入回复内容并发送，该消息携带对被引用消息 serverMsgId 的引用关系。
3. 接收方看到的回复消息上方展示引用摘要，点击摘要后聊天页自动滚动定位并高亮原消息（若原消息已被撤回或本地不存在，提示"原消息不可用"）。

## 5. 验收标准

**MSG-01 文本消息发送**
- Given 用户在输入框输入不超过 5000 字符的文本，When 点击发送，Then 消息立即在聊天页展示为"发送中"状态，随后在网络正常情况下于 2 秒内更新为"已发送"。

**MSG-03 图片消息**
- Given 用户从相册选择 3 张图片，When 点击发送，Then 三张图片作为独立消息按选择顺序依次发出，聊天页展示各自的缩略图。

**MSG-04 语音消息**
- Given 用户按住录音按钮说话 65 秒后松开，When 松开时长超过 60 秒上限，Then 系统按 60 秒截断并提示"语音已达最大时长"，仍正常发送前 60 秒内容。

**MSG-06 文件消息大小限制**
- Given 用户选择一个 600MB 的文件发送，When 点击发送，Then 系统在上传前拦截并提示"文件超过 500MB，无法发送"，不发起上传。

**MSG-09 消息状态机**
- Given 发送方发出一条消息且接收方设备在线并打开该聊天页，When 消息依次经过服务端接收、投递、接收方阅读，Then 发送方侧该消息状态依次更新为"已发送"→"已送达"→"已读"，且不会出现状态倒退（如已读后又变回已送达）。

**MSG-10 失败重发**
- Given 一条消息因网络中断发送失败，状态显示为"失败"，When 用户点击重发图标且此时网络已恢复，Then 消息重新提交并成功变为"已发送"，且在会话中的展示位置保持在原发送时间对应的位置，不跳到消息列表末尾。

**MSG-11 消息撤回**
- Given 用户在消息发出后 90 秒选择撤回，When 撤回请求提交，Then 该消息在发送方与接收方界面均实时替换为撤回提示；Given 用户尝试撤回一条发出已超过 2 分钟的消息，When 撤回菜单选项已不可见或点击后被拒绝，Then 原消息内容保持不变。

**MSG-12 消息转发**
- Given 用户选择一条图片消息并转发给另一个好友，When 转发提交成功，Then 目标会话中新增一条内容相同的图片消息，原消息的发送状态不受影响。

**MSG-13 引用回复**
- Given 用户对一条历史消息发起"回复"并发送新内容，When 消息发出后，接收方查看该消息，Then 消息上方展示被引用消息的摘要，点击摘要后聊天页跳转并高亮原消息。

**MSG-14 消息本地删除**
- Given 用户在自己的聊天页删除一条消息，When 删除操作完成，Then 该消息仅从操作者本机的消息列表消失，对方设备上的该消息展示不受任何影响。

**MSG-15 消息时序展示**
- Given 用户设备本地时钟与服务端时间存在偏差，When 用户发送并接收多条消息，Then 聊天页消息排列顺序以服务端时间戳为准，不因本地时钟偏差导致乱序。

**MSG-16 消息去重**
- Given 客户端因网络波动对同一条消息发起了两次提交请求（均携带相同 clientMsgId），When 服务端处理这两次请求，Then 仅生成一条有效消息记录，客户端断线重连后拉取消息也不会展示重复的两条消息。

**MSG-02 表情消息**
- Given 用户在输入框中输入 Unicode Emoji 或选择系统内置表情包中的一个表情，When 点击发送，Then 消息以对应的表情图像/字符正确展示在聊天页，且在接收方设备上渲染一致。

**MSG-05 视频消息**
- Given 用户选择一段时长 4 分钟、大小 80MB 的视频发送，When 点击发送，Then 视频正常上传并生成消息，聊天页展示视频首帧封面与时长标签，点击可播放。

**MSG-17 超限拦截提示**
- Given 用户录制的语音已达 60 秒上限并继续按住不松开，When 达到上限的瞬间，Then 系统自动停止录制并提示"已达最大时长"，不因用户未松手而丢失已录制内容。

## 6. 边界与异常场景

- **弱网发送超时判定**：消息提交后 15 秒未收到服务端确认，客户端自动将状态置为"失败"并停止等待，用户可手动重发；不做无限期等待。
- **撤回时间窗口边界**：以服务端记录的消息发出时间为准计算 2 分钟窗口，避免客户端本地计时误差导致误判；窗口边界（如恰好 120.0 秒）以服务端收到撤回请求的时刻是否 ≤ 120 秒为准。
- **群聊中的撤回权限**：普通成员仅能撤回自己发出且在时间窗口内的消息；群主/管理员的撤回权限扩展规则见 [群聊](05-group-chat.md)。
- **向已被拉黑或已删除好友的对象发送消息**：发送前客户端不做拦截提示，提交至服务端后被服务端拒绝，消息状态显示为"失败"，附加提示"对方拒绝接收消息"，不透露具体是拉黑还是已注销等原因。
- **多端同时操作同一条消息**（如手机端与桌面端同时撤回）：服务端以先到达者为准执行撤回，后到达的撤回请求返回"消息已被撤回"，不报错阻断，客户端据此静默同步状态。
- **断线重连后的消息补齐与去重**：客户端重新连接后拉取离线期间的消息，服务端返回的消息集合与本地已有消息按 serverMsgId 去重合并，避免同一条消息在列表中出现两次。
- **超大文件上传中断**：支持断点续传，网络恢复后从中断位置继续上传而非重新开始；若续传失败超过 3 次，标记为发送失败，需用户手动重新发起。
- **合并转发的嵌套限制**：合并转发的聊天记录卡片本身不可再次被选中加入新的合并转发，避免无限嵌套；用户仅能将该卡片作为单条消息整体再次转发。
- **引用的原消息已被撤回或删除**：引用回复消息本身正常展示，但点击摘要跳转时提示"原消息不可用"，不影响回复消息本身的可读性。
- **极限值**：文本消息 5000 字符上限、语音 60 秒上限、视频 5 分钟/100MB 上限、文件 500MB 上限、合并转发单次最多勾选 100 条消息。
- **消息发送对象状态变化**：发送过程中若接收方账号恰好被注销或所在群解散，服务端拒绝投递，发送方消息状态置为"失败"并提示"会话已失效"。
- **群聊场景下的送达/已读语义差异**：群聊中"已读"通常改为展示已读人数（如"3人已读"），完整送达/已读回执的群聊差异化规则见 [群聊](05-group-chat.md)，本文档仅约定单聊下的标准三段式状态机。
- **消息内容命中安全审核策略**：文本、图片等消息在提交时可能被内容安全系统拦截，发送方收到"消息包含违规内容，发送失败"提示，接收方不会看到任何痕迹，避免误伤正常沟通体验的同时符合安全与合规要求，详见 [安全与合规](10-security.md)。
- **撤回后再引用**：一条消息被撤回后，此前已经引用过它的历史回复消息不受影响，仍展示撤回前抓取的摘要快照，仅新的跳转定位行为会提示"原消息不可用"。

## 7. 依赖关系

- 消息的发送权限受 [关系链](02-relationship.md) 中好友关系与黑名单状态约束（拉黑后消息被拒收）。
- 单聊场景下的输入状态、消息交互细节在本文档基础上扩展，详见 [单聊](04-direct-chat.md)。
- 群聊场景下的撤回权限扩展、@提醒等在本文档基础上扩展，详见 [群聊](05-group-chat.md)。
- 消息状态机（MSG-09）与去重原则（MSG-16）是 [多端同步与漫游](07-multi-device.md) 实现多端已读同步与消息漫游的产品前提。
- 新消息到达时的离线推送策略，详见 [通知推送](08-notification.md)。
- 消息内容的安全审核与举报处理机制，详见 [安全与合规](10-security.md)。
