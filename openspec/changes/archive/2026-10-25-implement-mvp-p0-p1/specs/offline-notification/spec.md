## Purpose

定义当用户没有可实时呈现消息的在线设备时，平台如何通过系统推送触达用户，并处理免打扰、@提醒、隐私预览、角标、多端抑制和通知交互。

## ADDED Requirements

### Requirement: 推送 Token 与通知设置（NT-01, NT-06, NT-07）

SDK SHALL 支持注册、更新和注销设备推送 Token，并读写推送总开关与内容预览开关。用户关闭推送总开关后，平台 MUST 停止所有系统推送；关闭预览后 MUST 使用隐私模式文案。

#### Scenario: 关闭推送总开关
- **WHEN** 用户关闭推送总开关
- **THEN** 后续新消息不产生 APNs、FCM 或厂商通道推送

#### Scenario: 注销失效 Token
- **WHEN** 客户端上报某个推送 Token 已失效
- **THEN** 平台停止向该 Token 发送通知且不影响同账号其他设备

### Requirement: 离线推送决策树（NT-04, NT-05, NT-09, NT-10）

平台 SHALL 仅在接收用户没有可实时呈现消息的在线设备时触发系统推送。会话免打扰 MUST 抑制普通消息推送；群聊中@当前用户或@全体 MUST 穿透免打扰；桌面端活跃时手机端对同一消息 MUST 不重复推送。

#### Scenario: 离线接收新消息
- **WHEN** 用户全部设备离线时收到新消息
- **THEN** 平台向有效推送 Token 发送一条对应会话通知

#### Scenario: 免打扰群中的@提醒
- **WHEN** 免打扰群中出现@当前用户的消息
- **THEN** 平台仍发送带@提醒语义的推送

### Requirement: 推送内容与隐私模式（NT-02, NT-03）

推送内容 SHALL 默认包含发送者昵称和消息摘要，群聊额外包含群名称；隐私模式 MUST 只展示“你收到一条新消息”。媒体消息 MUST 使用类型占位摘要，不得包含媒体正文或敏感 URL。

#### Scenario: 隐私模式下隐藏发送者
- **WHEN** 用户关闭推送内容预览并收到群消息
- **THEN** 通知文案为统一的隐私模式文案，不包含发送者、群名或消息摘要

### Requirement: 通知角标（NT-08）

平台 SHALL 提供跨会话的未读总数用于通知角标，仅统计未开启免打扰的会话。用户标记已读、删除会话或消息规则变化后，角标 MUST 使用服务端权威未读数刷新。

#### Scenario: 免打扰会话不计入角标
- **WHEN** 用户有一个普通会话未读 3 条和一个免打扰会话未读 20 条
- **THEN** 应用角标显示 3

### Requirement: 通知点击、合并与权限引导（NT-11, NT-12, NT-13）

SDK SHALL 将通知点击解析为目标会话深链；同一会话短时间多条通知 MUST 合并或折叠为一条摘要。Web Demo MUST 在合适时机提示用户开启浏览器通知权限，并正确处理拒绝状态。

#### Scenario: 点击通知进入会话
- **WHEN** 用户点击一条携带 `conv_id` 的推送通知
- **THEN** 应用打开对应会话并定位最新未读消息

### Requirement: 推送可靠性与可观测性

平台 SHALL 通过可插拔通道发送推送，支持失败重试、过期 Token 清理、幂等键、发送结果指标和 DLQ 告警。重复消费同一消息事件 MUST 不产生重复用户通知。

#### Scenario: 推送通道暂时失败
- **WHEN** 推送提供商返回可重试错误
- **THEN** 平台在重试窗口内再次发送，且同一消息使用稳定幂等键
