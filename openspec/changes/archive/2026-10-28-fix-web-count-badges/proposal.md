## Why

Web IM 当前的未读角标依赖聊天页挂载状态：用户停留在通讯录或个人中心时，左侧“消息”按钮无法实时反映新消息；打开会话后也可能因刷新时序重新出现旧未读数。同时，各页面数字角标的超限显示规则不一致。

## What Changes

- 左侧导航栏“消息”按钮展示所有非免打扰会话的权威未读总数，并在 `message`、`sync`、`conversation` 事件后持续刷新。
- 用户打开未读会话并成功标记已读后，导航角标扣除该会话的真实未读数；全部未读清除后角标消失。
- 所有数字角标统一采用 `1-99` 显示真实数字、`100` 及以上显示 `99+` 的规则。
- 数字角标仅改变视觉显示，内部继续保留真实数量，并提供包含真实数量的无障碍描述。
- 免打扰会话继续不计入导航未读总数，会话列表按既有规则展示非数字未读标识；文字状态标签和正文数字不应用 `99+` 规则。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-im-consumer-web`: 明确导航栏未读角标的跨页面实时更新、打开会话后的扣减，以及所有数字角标统一的 `99+` 超限显示规则。

## Impact

- Web UI：`App.tsx`、`ChatsView.tsx`、`ContactsView.tsx`、通用数字角标组件及相关样式。
- SDK 适配层：暴露会话分页中的权威 `badge_count`，供导航角标使用。
- 测试：补充通用角标格式化单测，以及跨主导航页收消息、打开会话后扣减和免打扰排除的 Playwright 场景。
- 规格：更新 `web-im-consumer-web` 的行为场景；现有后端、OpenAPI 和 protobuf 无需变更。
