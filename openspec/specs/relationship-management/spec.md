# relationship-management Specification

## Purpose

定义 PaaS 模式下由平台托管的关系链能力，包括用户发现、好友申请、好友资料、分组、删除、黑名单和二维码名片，并向多端提供关系变更同步。

## Requirements

### Requirement: 用户发现与好友申请创建（REL-01, REL-02, REL-04）

平台 SHALL 支持按 Phantom ID 精确搜索用户并发起好友申请。手机号发现 MUST 由接入方用户体系完成，平台不得存储手机号或隐私设置；接入方解析出 Phantom ID 后使用同一添加接口。申请可附最多 30 字的验证消息，并可从用户资料卡或群成员入口发起。

#### Scenario: 按 Phantom ID 发起申请
- **WHEN** 用户输入一个存在且属于当前应用的 Phantom ID 并提交好友申请
- **THEN** 平台创建待处理申请，并允许附带不超过 30 字的验证消息

#### Scenario: 手机号发现由接入方完成
- **WHEN** 接入方在自己的用户体系中通过手机号找到目标用户
- **THEN** 接入方使用解析后的 Phantom ID 调用平台好友申请接口，平台不接收或保存手机号

### Requirement: 好友申请处理与列表（REL-05, REL-06, REL-07）

接收方 SHALL 能通过、拒绝或忽略申请，并通过申请列表查看待处理和历史记录。未处理申请 MUST 产生未读提醒；重复申请、已是好友和并发处理 MUST 返回确定且幂等的结果。

#### Scenario: 通过好友申请
- **WHEN** 接收方通过一条待处理申请
- **THEN** 双方建立好友关系，双方好友列表更新，并分别收到关系同步事件

#### Scenario: 并发处理同一申请
- **WHEN** 用户两台设备同时通过同一好友申请
- **THEN** 仅首个处理成功，另一个请求返回申请已处理且不重复建立关系

### Requirement: 好友列表、备注与分组（REL-09, REL-10, REL-11）

平台 SHALL 提供好友列表并按名称排序，支持特别关心置顶、好友备注和自定义分组。备注 MUST 仅对设置者可见，并优先于昵称展示；删除分组 MUST 不删除好友，成员归入默认分组。

#### Scenario: 备注在所有关系场景生效
- **WHEN** 用户为好友设置备注
- **THEN** 会话列表、聊天标题和可展示该备注的关系场景使用新备注

#### Scenario: 删除自定义分组
- **WHEN** 用户删除一个包含好友的自定义分组
- **THEN** 分组被删除，好友仍存在并归入默认分组

### Requirement: 删除好友与黑名单（REL-12, REL-13, REL-14, SEC-15）

删除好友 MUST 为单向操作且不通知对方。用户 SHALL 能拉黑好友或非好友、查看黑名单并解除拉黑；拉黑 MUST 自动解除好友关系并阻断新消息、好友申请和受限资料访问，解除拉黑后仅恢复为陌生人状态。

#### Scenario: 单向删除好友
- **WHEN** 用户 A 删除好友 B
- **THEN** A 的好友列表移除 B，B 仍保留 A，直到 B 主动删除

#### Scenario: 拉黑后阻断申请和消息
- **WHEN** 用户 A 拉黑用户 B，B 随后发送消息或好友申请
- **THEN** 平台拒绝或静默阻断请求，A 不收到通知

### Requirement: 自动通过、好友上限与二维码名片（REL-03, REL-08, REL-15, REL-16）

平台 SHALL 支持用户开启好友申请自动通过、单账号最多 10,000 名好友，并支持生成、刷新和扫描个人二维码名片。二维码刷新后旧码 MUST 失效，好友数量超限 MUST 拒绝新增关系。

#### Scenario: 自动通过申请
- **WHEN** 接收方已开启自动通过且收到新的有效好友申请
- **THEN** 平台立即建立双向好友关系并同步双方

#### Scenario: 刷新二维码后旧码失效
- **WHEN** 用户刷新个人二维码名片后扫描旧二维码
- **THEN** 平台提示二维码已失效且不展示可添加的目标用户

### Requirement: 关系变更多端同步（REL-06, REL-07, REL-12, REL-13）

好友申请到达、申请处理、好友删除、拉黑、解除拉黑、备注和分组变更 MUST 写入用户同步 Timeline，并以 `RelationEvent` 或 `ProfileEvent` 下发给在线端和后续离线端。

#### Scenario: 离线端补齐关系变更
- **WHEN** 用户离线期间好友申请被通过
- **THEN** 用户重新上线后通过 `SyncReq` 获取对应关系事件并更新好友列表
