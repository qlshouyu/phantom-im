# message-path-observability Specification

## Purpose

定义消息从客户端点击发送、服务端收单、Outbox 发布、fanout、在线推送到设备 ACK 各阶段的可观测性与性能验收方式，使消息延迟问题能够被分段定位并防止回归。

## Requirements

### Requirement: 消息链路阶段指标与关联标识

平台 SHALL 按 `msg_id` 和 `client_msg_id` 关联消息发送链路，并记录至少以下阶段的计数与耗时分布：发送请求受理、基础校验、风险检查、关系校验、乐观回显、幂等检查、取号、消息与 Outbox 提交、Outbox 发布延迟、fanout 用户 Timeline 写入、路由查询、WebSocket 推送、设备 ACK 和发送端端到端时延。指标 MUST 支持 P50/P95/P99，且日志 MUST NOT 记录完整消息内容或审核规则细节。

#### Scenario: 单条消息可分段定位
- **WHEN** 一条在线单聊消息完成从发送到接收端 ACK 的全流程
- **THEN** 运维人员可以使用 `msg_id` 或 `client_msg_id` 找到各阶段耗时，并区分慢在收单、Outbox、fanout、路由还是 WebSocket 推送

#### Scenario: 风险检查关闭时可识别跳过
- **WHEN** 应用关闭风险检查并发送消息
- **THEN** 指标标记风险检查为跳过状态，而不是记录为零耗时的实际审核

#### Scenario: 慢设备可观测
- **WHEN** 某在线设备推送超时或被投递队列拒绝
- **THEN** 平台记录对应设备类型、超时/拒绝计数和路由维度，但不记录消息正文

### Requirement: 可重复发送延迟基准与验收

项目 SHALL 提供可重复的 1v1 在线发送基准，使用生产式启动参数、预热流量、固定发送速率和 P50/P95/P99 报告。参考环境在预热后以不超过每秒 20 条发送 1000 条文本消息时，`SendMsgResp` P95 MUST 不高于 50ms，接收端端到端 P95 MUST 不高于 100ms，P99 MUST 不高于 200ms；同环境变更前后 MUST 使用相同脚本和配置对比。

#### Scenario: 发送确认达到目标
- **WHEN** 在参考环境完成预热并发送 1000 条合法单聊文本消息
- **THEN** 发送确认时延的 P95 和 P99 满足约定阈值，报告包含样本数、失败数和环境配置

#### Scenario: 接收端到端达到目标
- **WHEN** 收发双方均保持在线且无人工注入故障
- **THEN** 从发送调用开始到接收端收到 `MsgPush` 的端到端 P95 和 P99 满足约定阈值

#### Scenario: 延迟目标未达成时阻断回归
- **WHEN** 相同基准脚本的 P95 或 P99 超过阈值
- **THEN** 验证结果判定失败，并输出按阶段聚合的耗时摘要用于定位

#### Scenario: 故障场景不伪装为低延迟
- **WHEN** 基准期间出现 CPU、数据库、MQ 或网络故障
- **THEN** 报告必须记录故障注入和失败样本，不得仅删除慢样本后宣称通过
